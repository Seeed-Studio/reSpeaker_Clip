# Release 0.1.5 (pre-release)

## Overview

Stabilization release: 76 changes since v0.1.4. Three headline fixes — the
**overnight recording-timestamp corruption** (a soft-clock arithmetic bug that
could also silently overwrite an older recording with a newer one), the
**VBUS false-positive that blocked power-off on battery**, and a class of
**freeze/stack-overflow bugs during sync and shutdown** — plus the RTC live
streaming feature, a storage GC, battery calibration, and the AT protocol
hardening and documentation overhaul around them.

## Changes

### Recording timestamps replayed the past (root cause)

`clip_get_current_time()` decomposed elapsed time with per-unit carry loops
over `uint8_t` fields — minutes wrapped modulo 256, silently discarding every
4 h 16 m of elapsed time. More than 4 h 16 m after the last clock rebase (a
recording stop or `AT+TIME`), the computed clock **replayed a past time**:
the next recording deterministically re-minted a previous session's ID
(YYYYMMDDHHMMSS), the storage layer tolerated the directory collision, and
the new audio was written into the old session's directory — new content,
yesterday's date. All clock arithmetic is now wide-type division/modulo with
the full hour/min/sec base composed in.

### VBUS false positive refused power-off on battery

The battery VBUS-presence read used the raw charger status register —
non-presence bits read as "USB attached", so a long-press power-off on
battery logged `USB power present, ignore power off` and the device would
not shut down. Presence is now read through the masked attribute.

### Freeze class: stack overflows and SD walks on the wrong threads

- Transfer-thread and boot-time main-thread stack overflows in the session
  scan (walker buffers are now static under a mutex).
- The STOP handler walked the SD card on the event thread — froze the
  device when a transfer was reading concurrently (removed; the untransferred
  indicator is now a persisted flag verified by a newest-first scan).
- Shutdown thread stack 2048 → 4096 (same overflow class).
- The 15 s periodic `fs_sync` starved the audio pipeline (DMIC timeouts
  every 15 s) — durability is now close-time syncs plus a deferred
  unsynced-flag write.
- A STOP issued during the 1.5–4 s recording-start window was silently
  swallowed (no log, no buzz, machine wedged in RECORDING). The dispatcher
  now routes it through `audio_stop_recording()`'s pending-start path.
- WiFi AP start/stop blocked the event dispatcher for seconds (RPU boot,
  AP-enable retries) — buttons and the UI froze during `AT+WIFI=on`. The
  blocking work moved to a dedicated WiFi worker thread; `AT+WIFI` keeps its
  response timing (ok:true ⇒ SSID connectable).

### Storage: husk sessions, honest deletes, on-demand cleanup

- 0-byte .opus files are deleted on encounter; sessions that end with no
  audio are refused at `AT+DOWNLOAD` (`ok:false`) instead of looping the app.
- The husk gate exempts the ACTIVE recording session (a live recording's
  first file reads 0 bytes before its first flush).
- `AT+DELETE` prunes empty date/hour/minute parents and reports real errors;
  empty session directories no longer accumulate.
- **On-demand cleanup (`AT+GC`)**: reclaims empty leftovers (power cuts in
  the first write window, aborted starts, stale-json phantoms — the on-disk
  walk is the authority; 0-byte chunks are not audio, a stale json is not
  evidence) and fully-synced sessions (every file already on a host), on
  explicit request. Bookmarks never block reclamation (a mark is a
  position inside audio; without the audio it points at nothing). Never
  touches unsynced audio or live sessions; deletion is on-demand only,
  never automatic. Session
  create/delete are serialized;
  `storage_create_session` refuses an existing tree instead of rewriting
  metadata over it.
- The untransferred (unsynced audio) indicator survives reboots as a
  persisted flag, verified against the newest sessions on mount.

### Battery

- Critical-battery protection: graceful stop at 3 %, recording lockout until
  recovery (8 % or charging); low-battery UI warning stays.
- Idle-current feed to the nRF Fuel Gauge re-measured: 250 → **350 µA**
  (production build at 3.7 V); fuel-gauge state format v4 re-anchors
  existing devices on first boot.
- `AT+BATT` exposes `soc_raw` alongside the smoothed display percentage.

### RTC live streaming (new feature)

`AT+START=rtc` streams live Opus audio over the BLE FILE_DATA
characteristic (`STREAM_START/DATA/END`), bounded drop-oldest queue,
no SD session. Sessions auto-abort 5 s after START without `AT+DOWNLOAD`,
or on BLE disconnect; `AT+PAUSE/RESUME` apply, `AT+MARK` is rejected.
Button long-press still always records to SD. SDK: `clip.listen` receiver
with jitter buffer, latency stats, and `--pause-at/--resume-at`.

### AT protocol

- **`AT+SN`** (factory): write-once product serial number; rewrite requires
  echoing the device MAC. `AT+SN?` returns MAC + SN for the factory station.
- **`AT+TIME?`** reports `restored` (clock from boot persistence, needs a
  live sync) and `uptime` (silent-reboot forensics). Time is persisted at
  recording stop and at power-off.
- `AT+AUTODEL` removed (stored but never enforced); the `stereo` START alias
  removed (firmware is mono-only).
- `AT+FACTORY` / `AT+PAIR=reset` require explicit confirmation, refuse while
  recording/transferring, and report honest failures.
- `AT+DOWNLOAD` re-issue while the same transfer is running answers OK
  (idempotent); a busy device answers `EBUSY` immediately instead of
  stalling 3 s.
- Full AT response tracing on the debug console (no truncation).

### Tools & tests

- `samples/wifi_sta_iperf`: STA-mode throughput test (port of the AP iperf
  sample) — `wifi connect <ssid> <psk>`, iperf2-compatible UDP upload up to
  24 h with a 5 s progress reporter. Chinese usage doc included.
- `tests/re` joins the MCUboot build (serial-DFU upgradable).
- `tests/clip`: per-device BLE name / AP SSID from chip ID.
- USB serial number descriptor now derives from hwinfo (unique per device).

### Documentation

- `docs/protocol.md` fully audited against the firmware **and translated
  (`protocol.zh-CN.md`)**; architecture/power/troubleshooting aligned;
  power budget re-measured at 3.7 V.

## Known issues

- A same-second stop → immediate re-start can overwrite the previous take's
  first chunk (`-EEXIST` is tolerated and `storage_create_file` writes from
  offset 0 without truncation). Mint-side ID uniqueness is the planned fix.
- WiFi AP stays up while a client is associated (auto-off only fires with no
  client); an associated-but-idle phone keeps the radio on (~59 mA).
- The soft clock loses the powered-off interval (no RTC hardware); hosts
  should answer `restored:true` with one `AT+TIME` sync.

## Upgrade notes

- App-core + network-core OTA as usual (both images in the ota.zip); USB
  serial DFU and BLE OTA both work. Users on v0.1.4 or earlier should
  re-sync time (`AT+TIME`) after the first boot — the clock fix invalidates
  the persisted base of a long-running device only in the sense that old
  timestamps may have been wrong; no data migration is needed.
- First boot re-seeds the fuel-gauge state (format v4).
