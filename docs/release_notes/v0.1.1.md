# Release 0.1.1 (pre-release)

## Overview

Interaction-latency release for the main application: stopping a recording
from the button now confirms **instantly** (haptic + screen) instead of after
the SD flush, and a flush-time bug that could mis-trigger power-off when
pressing the button during the flush window is fixed. The hardware-test
firmware gains per-device wireless identities for production-jig RSSI
locking, and the documentation set received a full accuracy overhaul.

> **Pre-release** — published automatically by CI; promote to a full release
> after verification.

## Changes

### Button stop-recording: instant feedback, no more mis-triggered power-off

Two related fixes to the long-press stop path:

- **Feedback now posts before the flush.** The STOP handler previously ran
  the file flush (`fs_sync` on the SD card) *before* the confirmation buzz
  and screen update — on a busy card (e.g. transferring while recording)
  the buzz came hundreds of ms late and the stop felt laggy. The handler now
  fires the haptic pattern and UI update first; the flush completes behind
  them, hidden inside the ~300 ms double-buzz window.
- **The button driver no longer blocks on the event handler.** STOP was
  posted *synchronously* from the button driver's 30 ms polling thread, so
  during the flush the press-duration accounting froze while wall-clock time
  kept running. On unblock, the accumulated hold time could jump past the
  3 s LEVEL_1 threshold and trigger an unintended **power-off** when the
  user pressed the button during the flush window. STOP is now posted
  asynchronously — the driver thread never blocks.
- Haptic patterns moved to a dedicated low-priority thread (patterns are
  100–500 ms of `k_sleep`); every caller now returns immediately, so neither
  the event thread nor the button driver is ever held by the motor timing.
- `AT+STOP` no longer plays a redundant third buzz: the AT handler used to
  add its own `HAPTIC_SHORT` after the event handler's `HAPTIC_DOUBLE` —
  previously masked by the old timing, it became a clearly separated extra
  buzz once feedback moved ahead of the flush. Stop feedback now comes from
  the event handler only (button and AT paths identical).
- Six boot-banner log lines trimmed to offset the flash cost (the app region
  was at 99.97%); `audio.c` fixed the same `.dt_flags` truncation bug class
  as `tests/clip` (a `gpio_dt_spec` 16-bit flags field silently dropped
  `GPIO_OUTPUT`).

### Battery: 0% displayed at a healthy voltage

A device left idle (e.g. overnight, WiFi never started) could wake up
showing **0%** while the cell measured ~4.0 V. The fuel-gauge state had been
drained to empty and the display's directional latch (anti-churn, by design)
forbids any upward movement while discharging — a bottomed-out value was
locked in until the next charge session. Three fixes:

- **Stale-state heal at boot**: if the persisted display seed is ≥20% below
  what the boot-time voltage says, the restored coulomb-counter state is
  discarded and the gauge re-estimates from voltage (same path as a
  factory-fresh boot; subsequent tracking and persistence are unchanged).
- **Re-anchor escape while discharging**: a large upward gap (≥20%) between
  the gauge and the displayed value now catches up at the normal
  3%/poll rate instead of being held; small anti-churn corrections remain
  latched as designed.
- **WiFi load compensation keyed on association**: the unseen-current
  estimate (nRF7002 is powered upstream of the PMIC sense resistor) is no
  longer applied merely because the AP is up — an idle client-less AP
  contributed nothing. Previously a beaconing AP with no station was billed
  59 mA continuously, phantom-draining the coulomb counter to empty within
  hours while the real draw was far lower.

### Test firmware: per-device identity for production jigs

`tests/clip` derives a unique 6-hex-digit token from the nRF5340 FICR device
id and applies it to **both** the BLE advertising name and the WiFi AP SSID
(`Clip_<6hex>`, stable across reboots/reflashes), so a production jig can
lock RSSI/identity to one board among many simultaneously powered boards.
The `ident` shell command prints the name/MAC/SSID/token in one line.
`sys stop` now also cancels the 1 s battery/OLED refresh work before
shutting down (it kept waking the CPU every second and writing to the
unpowered display), and the image builds with zero compiler warnings
(`bt_hci_cmd_alloc` migration, `net_addr_pton`, dt-flags fixes).

### Documentation overhaul

Full accuracy audit (139 findings fixed: dead references, stale facts,
protocol corrections) plus a documentation-system restructure: doc map with
single-source-of-truth table (`docs/README.md`), new `CONTRIBUTING.md`,
`docs/release_process.md`, `docs/power.md`, `docs/troubleshooting.md`;
READMEs added for `applications/clip`, `tests/battery_cycle`, `tests/re` and
four samples; `tests/clip` README bilingual sync. Production build commands
kept the required `-DSNIPPET_ROOT` form (sysbuild does not search app-dir
snippets).
